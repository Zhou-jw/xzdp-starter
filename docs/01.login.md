# Thrift
```thrift
// ./hello.thrift
namespace go hello.example

struct HelloReq {
    1: string Name (api.query="name"); // 添加 api 注解为方便进行参数绑定
}

struct HelloResp {
    1: string RespBody;
}

service HelloService {
    HelloResp HelloMethod(1: HelloReq request) (api.get="/hello");
}

```

1. namespace go hello.example：指定生成代码的语言和包名
```thrift
// ./hello.thrift  —— 文件名为hello，后缀.thrift是Thrift IDL的标准后缀
namespace go hello.example  —— 核心：指定生成Go语言代码的「包名」为hello.example
```
- 语法：namespace 目标语言 包名/命名空间，是 Thrift IDL 的 **必选配置**；
- 作用：告诉 Thrift 编译器「生成 Go 语言代码时，将代码放在 hello.example 包下」；

2. 定义请求参数结构体：`HelloReq`
```thrift
struct HelloReq {  // 定义「请求参数结构体」，命名为HelloReq（驼峰命名，规范写法）
    1: string Name (api.query="name");  // 结构体的字段定义（核心行）
}
```

- `struct`：Thrift IDL 中定义复杂数据结构的关键字（类似 Go 中的 struct、Java 中的 class），用于封装多个请求 / 响应字段；
- `1:`：字段的唯一标识号（Thrift 核心特性），从 1 开始递增，不可重复 / 修改——Thrift 底层通过这个数字标识字段，而非字段名，即使后续字段名修改，只要数字不变，老版本客户端仍可正常调用（保证接口向前兼容）；
- `string Name`：定义字段类型为字符串（string），字段名为 Name（后续生成 Go 代码后，字段名会映射为 Name string）；
- `(api.query="name")`：Thrift 扩展注解（适配 HTTP 场景）—— 核心用于「参数绑定」，告诉生成的 HTTP 框架（如 Hertz）：将该字段绑定到 URL 的查询参数中，查询参数的键为 name（即请求时通过 ?name=xxx 传递参数）。

3. 定义响应数据结构体：`HelloResp`
```thrift
struct HelloResp {  // 定义「响应数据结构体」，命名为HelloResp
    1: string RespBody;  // 响应字段：字符串类型，标识号1，字段名RespBody
}
```
作用：封装接口的返回数据，后续接口执行成功后，会将业务结果赋值给 RespBody 字段，返回给调用方；
无注解说明：该字段是响应体的核心数据，生成 HTTP 代码后，会直接序列化为 JSON 返回（如 {"RespBody": "hello, xxx"}）。

4. 定义服务与接口：HelloService + HelloMethod
```thrift
service HelloService {  // 定义「服务名」为HelloService，可包含多个接口方法
    HelloResp HelloMethod(1: HelloReq request) (api.get="/hello");  // 核心接口定义
}
```
- `service`：Thrift IDL 中定义服务的关键字，一个 service 可包含多个接口方法（类似 Go 中的接口 interface）；
2. `HelloResp HelloMethod(...)` ：定义接口方法—— 方法名 HelloMethod，返回值类型为 HelloResp（上面定义的响应结构体）；
3. `(1: HelloReq request)`：定义接口的入参—— 入参标识号 1（与 struct 字段标识号作用一致，保证兼容），入参类型为 HelloReq（上面定义的请求结构体），入参名 request；
4. `(api.get="/hello")`：HTTP 核心注解—— 告诉生成的 HTTP 框架（Hertz）：将该接口方法映射为 HTTP GET 请求，对应的URL 路径为 /hello；
扩展：注解支持所有 HTTP 方法，如 api.post="/hello"（POST 请求）、api.put="/user"（PUT 请求）等，与 RESTful 风格完全兼容。

cd src
